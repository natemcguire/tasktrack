# Nate's Software SSO

The canonical deployment is https://tasks.nates-software.com. The existing https://tasks.eastbayprojects.com address is a white-label hostname on the **same** `tasktrack` Worker, D1 database, Durable Object namespace and R2 bucket. It retains its hostname and displays East Bay Projects branding; the canonical host displays Tasks. Sign-in pages show a small “SSO provided by Nate’s Software” credit. Generated share, invitation, device sign-in and API resource links use the canonical hostname. Each hostname uses host-only cookies; either hostname can start SSO. There is no duplicate instance or synchronization layer.

The `AUTH_HUB` service binding points to Worker `auth`. `SSO_REQUIRED=1` disables independent public signup, email links and passkey *sign-in*. Passkey registration and removal and the approval password stay available on `/account` for the signed-in browser, because agent approvals and other step-up confirmations happen inside Tasktrack (2026-10-31: before this, the `/auth/` gate blocked `Add passkey` with `sso_required`, so nobody without a pre-SSO passkey could approve an agent). SSO membership must be active in tenant `nates-software`, with product `tasktrack`. The organization owner is `nate.mcguire@gmail.com`. Sign-up is open: `/signup` sends the browser to the hub's create-account page (`/authorize` with `intent=signup`), `/login` to its sign-in page, and the hub gives a new account the Tasktrack grant. Access can still be revoked per person at the hub. An invitation to a Tasktrack workspace alone cannot grant SSO access; the invited person creates or uses a hub account first.

Guest and invalid-session browser requests redirect to a public Tasks sign-in page. Its passkey sign-in button starts SSO at `/auth/sso/start`, preserving the safe return path. Callback failures show a clickable retry link and never bypass access checks. Browser login uses a random state bound to a secure HttpOnly cookie and consumed once in D1. The hub's fragment token is posted to the same-origin callback and exchanged server-side. The long-lived hub session is stored in D1, linked to the existing host-only Tasktrack session. Every protected request introspects the hub session. Shared task links and private previews require the same access.

The migration renames Nate's existing `nate@eastbayprojects.com` account to `nate.mcguire@gmail.com`, preserving its UUID, three workspaces and tokens. Verified email links existing users to their current IDs and workspaces, preserving all task data. A person who signs in with no workspace gets one of their own, as its admin, and cannot see any other workspace. Nobody joins another workspace, including the owner's, without one of its invitations; accepting one adds that workspace beside their own. People who were already members keep their workspaces and roles. Existing project, membership, agent and service-token scopes remain in force. API tokens check the owner's current SSO entitlement via the private service binding; service-app tokens check their creator's entitlement. Revocation fails closed, including hub outages.

Deployment adds migration `0013_sso.sql` without deleting or rewriting existing data. Local standalone development remains available when `SSO_REQUIRED` is unset. To exercise standalone hosted browser fixtures, explicitly override it to `0`.

The deployment script prefers the ignored `wrangler.private.json`; keep its canonical route, aliases, `SSO_REQUIRED`, and `AUTH_HUB` binding aligned with `wrangler.jsonc`. Existing `preview.eastbayprojects.com` remains an isolated preview origin, whose document reads recheck the associated SSO session.

The legacy `hello@tasks.eastbayprojects.com` sender remains configured for existing agent notifications; browser sign-in uses the central auth hub’s passkey flow; Tasks offers no email-link fallback.

Signing out calls the hub’s global browser logout endpoint before clearing the local session. All existing browser product tokens and hub sessions become invalid; a new explicit sign-in is required. Agent and service credentials retain their existing scopes and remain subject to live membership/product grants. A hub failure keeps the local session available to retry and never reports successful global logout.
